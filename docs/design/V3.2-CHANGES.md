# Encore design v3.1 and v3.2: everything that changed (13–18 Nov 2026)

**What this is.** The full list of design changes made after the v3 kit and the milestone 10/11 screens, with sizes, colours, words and behaviour, so the software chat can build them in native JUCE. It adds to `design/kit/DESIGN-SYSTEM.md`, `design/kit/SCREENS.md` and `design/kit/NEW-FEATURES-M10-M11.md`. **Where they differ, this file wins** until its content is merged into them in the repo kit (`docs/design/`).

**Design canvas:** https://claude.ai/artifact/VJEpVteR9LgtESUkfghhNC
- Page **"v3.1 — Audit fixes (13 Nov, to review)"**: boards AStage, AStageAlerts, AEdit, AMidi, APlugins, APreShow, ACueMenu, ARoutingIO, ARoutingSends, ABottomRow, ABottomRowLarge, ALayout.
- Page **"v3.2 — Working copy (from v3.1, 16 Nov)"**: the same boards copied as B… (BStage, BStageAlerts, BEdit, BMidi, BPlugins, BPreShow, BCueMenu, BRoutingIO, BRoutingSends, BBottomRow, BBottomRowLarge, BLayout) plus **BAmpBuilder**. **v3.2 is the current design.** v3.1 stays as it was for comparison.
- The v4 pages stay parked (not to build). Only two v4 pieces were taken into v3.2: the status bar (§5) and the menus (§6).

**Rules that still hold for everything below:** native JUCE only; tokens from `EncoreTheme.h` (a new value gets a new named token); kit components only; Inter; no animation; repaint only on change; the existing 30 Hz timer; words from the code; nothing pretends; live safety (no pop-ups on Stage, Mute always in the same place).

**Decisions from Adrian that shape this (keep them):**
- No blue accent bars or underlines as selection indicators: the existing selected fills are clear enough (audit F13 not applied).
- No light or whitish outlines on fields: fields keep the v3 dark border #0C0C0E (audit F14 not applied to fields).
- Keep the amps and pedals as they are in Edit; keep v3 (not v4) look apart from §5 and §6.
- No running-order progress bar.
- Avoid a card inside a card; spacing even on every side.
- Don't oversimplify: it must feel like robust PC software, not a tablet app.

## 2. Toolbar: one Settings button (v3.1 and v3.2)
- **"MIDI…" and "Audio…" are replaced by one button "Settings…"** with a 13 px gear icon before the text. Same button style as the others (24 px, `.b`).
- Tooltip: **"Settings: Audio, MIDI and Plugins (opens on the tab you used last)"**.
- It opens the existing Settings window (tabs Audio | MIDI | Plugins) on the tab used last (remember it per computer in `AppSettings`; first time: Audio).
- Behaviour kept: any keyboard shortcut or menu item that opened the Audio or MIDI tab still opens that tab directly. Plugins needs no separate way in.
- Order on the Edit toolbar (right side): Tuner · Settings… · Out slider + dB field · PANIC · MUTED.
- The "−12.0 dB" field next to the Out slider never wraps (one line, 66 px).

## 3. Bottom row of the main window (v3.1 and v3.2)
Boards: **ABottomRow / BBottomRow** (collapsed) and **ABottomRowLarge / BBottomRowLarge** (mixer view). This replaces NEW-FEATURES §B.4 and the bottom row in SCREENS §4.4.

### 3.1 Two views
- **Collapsed** (the default): 104 px high, horizontal output strips.
- **Mixer view** (opened): 196 px high, vertical strips with a dBFS meter, peak readout, level fader, limiter light and mute. The patch area above gives up 92 px while it's open.
- Switching: a **tab on the top edge of the Outputs pane** (see 3.4). The state is remembered per computer in `AppSettings`. No animation: the row simply changes height on click.

### 3.2 Collapsed (104 px)
Grid: `250 | 1fr | 116`, gap 8, same left column as the main grid.

**Input pane** (250, `.pane`, padding 10, gap 5, content centred vertically):
- Label "Input" (`.k`, 11.5 #A3A3AA).
- **Input picker** (`.pop` popup field, 22 high, full width): "**Guitar** · 1 · Input 1 (Mic/Inst) ⌄": the input name 600, then channel number and the interface's channel name in #9A9AA1, ellipsised. Tooltip: "Input of the playing patch. Pick another to change it for that patch." It lists this computer's input names (and a NOT HERE name if the patch uses one). Picking one changes **the playing patch's input** (same action as the IN tile in Edit). Today's bottom-row "Guitar input" picker already lives here, so no action is lost.
- Horizontal input meter: 8 px high, radius 4, track #0E0E10, fill green #2BC24F → yellow #E8CF3A at the top end; peak tick 2 px #E8E8EB.
- Removed: the "playing patch" caption.

**Outputs pane** (`.pane`, padding 10):
- **No header line, no "OUTPUTS" label, no count, no "M mutes one" text, no Compact | Full toggle.** The pane's accessible name and tooltip are "Outputs" / "Outputs on this computer. M mutes one."
- Strips **always share the width equally**, so all outputs (up to 8) fit. Nothing scrolls, nothing hides.
- Each strip: padding 0 12, divider 1 px #26262B on its left (the first strip has no divider and no left padding; the last no right padding), column with gap 5:
  - line 1: name 11.5/600 #E8E8EB, one line, ellipsised, **full name in the tooltip**; channels right-aligned 9.5 #8C8C93 tabular ("1/2", "5", "all").
  - line 2: meter(s) (stereo: two 4 px bars, gap 2; mono: one), then the **level value** (46 px, right-aligned, 10.5 #C4C4C9, tabular + slashed zero, "0.0 dB"), then **M** (MuteButton 24 × 20, radius 4).
  - **The value is always shown.** Muted: the value dims to #8C8C93, the M turns red (MUTED gradient, white M). **No "muted" word**: the red M says it.
  - When strips are narrow (8 outputs at 1440), the value moves to its own line under the meters (left-aligned) so the M keeps its place.
- Tooltips: M "Mute <name>"; name = full name.

**System health status** (116 px column, no pane, no title):
- A flat button (padding 6, radius 5, transparent; hover #232326), two lines, 11 px:
  - line 1: healthy: 6 px dot #30C25A + "Healthy" #9A9AA1. Something to check: amber warning icon 12 px + "**1 thing to check**" (600, #FFB340; "N things to check").
  - line 2: "CPU 9% · 5.3 ms" #8C8C93 (CPU and round-trip latency).
- Tooltip: the problem text first (e.g. "Output “Amp DI” is muted."), then "Click for system health details (CPU, dropouts, device, latency)."
- Click: opens the system health details (today's health lines, dropouts, overruns, limiter, device, sample rate, buffer, round trip, and **Reset counters**). The details' own look is still to design; until then use today's health lines in a small `DialogFrame` on Edit only (never a pop-up on Stage).
- Why: health matters live, but in Edit it shouldn't shout. Stage keeps its prominent health widget unchanged.

### 3.3 Mixer view (196 px)
Grid: `auto | 1fr | 116`, gap 8.

**Input strip** (`.pane`, padding 10 12), a grid `18 | 4 | 5 | 41` × rows `14 | 20 | 12 | 1fr`, row gap 6:
- "Input" label (`.k`); the **input picker** as a compact `.pop` (20 high, 11/600, "Guitar ⌄", full name in tooltip, same action as 3.2); the peak readout; the scale + one meter.

**Outputs pane** (`.pane`, padding 10 12): vertical strips **94 px wide** (the first 82, no divider), padding 0 12, divider 1 px #26262B. Each strip is one fixed grid so nothing can push anything else:
- columns `18 | 4 | 12 | 6 | 28` (scale · gap · meters · gap · fader column), rows `28 | 12 | 1fr | 20`, row gap 6.
- **Row 1, name** (all columns): 11/600, line height 14, **up to two lines** ("Front of / house"), then ellipsis. Tooltip "<name> · outputs 1/2". The channel numbers are only in the tooltip here.
- **Row 2:** **LIM** light over the meter (8.5/700 caps, letter-spacing .06em, #5E5E64, with a 5 px dot #2E2E33; when the output's safety limiter is working: text and dot #FFB340; draw it flat, no glow, per audit N1). Tooltip "Safety limiter at −1 dBFS" (+ " (working now)"). The **peak readout** centred over the fader column: 10 #C4C4C9 tabular, "−8.2"; **red #FF8A80 when the peak reached −1 dBFS** (the limiter); "—" when muted or silent. Tooltip "Highest level since reset. Click to reset." Click resets this output's peak (and clip count).
- **Row 3:** the **dBFS scale** (9 px #8C8C93, right-aligned, labels 0, −6, −12, −24, −48), the **meter** (stereo: two 5 px bars, gap 2; mono: one; radius 2; track #0E0E10), and the **level fader**.
  - Meter law (position from the bottom): 0 dB → 100 %, −6 → 82 %, −12 → 64 %, −24 → 38 %, −48 → 8 %, −60 → 0 (linear between). Fixed colour zones over the whole bar height: green #2BC24F up to 80 %, yellow #E8CF3A 90–97 %, red #E8483E from 98.5 %. Peak tick: 1 px #E8E8EB at the peak position.
  - **Fader** (28 px column): track 4 px #0E0E10, radius 2, inset 6 px top and bottom so the thumb never leaves its column; 0 dB mark 18 × 1 px #6E6E75; thumb 22 × 12, radius 3, gradient #5A5A60 → #3A3A3E, border #0E0E10, top highlight, a 1 px #F2F2F4 centre line. **Fader law** = the SendFader law (+6 → 0, 0 → 0.1, −6 → 0.25, −12 → 0.4, −24 → 0.6, −40 → 0.8, −∞ → 1). It drives the **output's level** (the same value as in Routing). Double-click → 0 dB. Tooltip "Level of <name>. Double-click for 0 dB."
- **Row 4:** the **level value** right-aligned under the meter (10.5 #C4C4C9, tabular, **no "dB" unit here**; "−∞" at the bottom; muted #8C8C93), and **M** (24 × 20, never shrinks) **centred exactly under the fader**.
- Muted output: no signal on the meter, peak "—", red M.
- With 3 outputs the strips keep their width (like a mixer) and the rest of the pane stays empty; 8 outputs fill it.

**System health status**: the same two-line status as collapsed, in the 116 px column, aligned to the bottom.

### 3.4 The tab (open / close)
- 44 × 12, sits on the **top edge of the Outputs pane, centred on that pane**, overlapping the 8 px gap above (top −7). Background = pane #1D1D20, border 1 px #0A0A0B without the bottom edge, radius 6 6 0 0.
- Chevron 10 px, stroke 3, #A3A3AA (hover #FFFFFF): **up** when collapsed, **down** when open.
- Tooltip / accessible name: collapsed "Open the mixer view: vertical meters, peaks and level faders"; open "Close the mixer view".

### 3.5 Data needed (all exist in milestone 11's §3.6)
Per output: name, channels, level dB (read and write), mute, peak meter L/R, limiter active, clip count, peak since reset. Input: name, channel, interface channel name, peak meter. Health: CPU %, round trip, dropouts, overruns, the warnings list. All on the existing 30 Hz timer; repaint only on change.

### 3.6 Removed on purpose
The OUTPUTS header and subtitle, the output count, "M mutes one", the Compact | Full toggle (Full only made strips wider and scrolled, which hides outputs mid-show), the "muted" word, the "playing patch" caption, and the System health card with its CPU/dropouts/latency lines (now in the details).

## 7. v3.2: layout editor, drag and drop (board BLayout, interactive)
- **Widget list:** every item is a button with a 6-dot grip on the right; cursor grab. Pane header hint "drag onto the stage". Tooltip "Drag onto the stage, or click to add it at the first free place".
- **Drag a widget from the list onto the stage:** while dragging, a **drop box** shows where it lands: dashed 2 px #4C8DF6, fill rgba(76,141,246,0.14), radius 6, text "Drop: <widget>" 12/600 #EEF3FD, **snapped to the 24 × 16 grid**. New widgets are 4 × 2 cells. On drop the widget is added and selected.
- **Move a widget on the stage by dragging it:** it keeps the point where you grabbed it; the original shows at 35 % while dragging; the drop box says "Move: <widget>"; it snaps to the grid.
- **Click selects** a widget: 2 px #4C8DF6 border with a 3 px rgba(76,141,246,0.25) ring, its tag turns blue (#2E6FDC, white text), resize handles (8 × 8 white, 1 px #2E6FDC border) on the right edge middle, bottom middle and bottom-right corner.
- Footer: "<N> widgets · 24 × 16 grid" (live count) and "Selected: <widget>"; inspector header "Widget · <widget>".
- Click in the list (no drag) adds the widget at the first free place.
- **Open question for Adrian:** what happens when a drop or move lands on cells another widget uses: push the others aside, take the nearest free space, or refuse the drop. Until decided: take the nearest free space of the same size; if there is none, refuse (the drop box turns amber, nothing moves).
- In JUCE: `DragAndDropContainer` on the editor, the list items as drag sources, the stage as `DragAndDropTarget`; the drop box is a light overlay component repainted only when the snapped cell changes.

## 8. v3.2: Amp builder (new feature, scheduled 18 Nov; board BAmpBuilder, interactive)
Full plan, decisions, rules and **how to build it** (data, assets, rendering, Edit integration, keyboard): **`design/AMP-BUILDER.md`**; the board's full source with every number: `design/boards/BAmpBuilder.dc.html`. Rendered layers and their asset list: **`design/textures/AMP-BUILDER-LAYERS.md`** (script `design/textures/render_amp_parts.py`). Short version:
- A full-area view in Edit (like Routing), sub-toolbar: amp icon + "Amp builder", the amp picker (menu "AMPS IN THIS SHOW", "New amp from a template...", "Add from the library..."), chip "IN THIS SHOW · IN LIBRARY", "Used by <patches>", Undo, Save amp, "Back to patches F8" (key to confirm).
- Three columns: **Parts** (220) | **Face** (the amp at its real 600 × 430, snap 2 px, drag to add and move, click to select) | **Inspector** (300; a part's settings, or the whole amp's when the body is clicked; then **Sound**: NAM capture, format line, Load capture…).
- A preset = **face + one NAM capture + default settings**, stored **in the show with a copy in the computer's library**; free placement starting from **templates** (British gold, Black panel, Plexi, Cream, Framed head, Grille head, Tweed top, Jazz clean).
- **Knobs either drive** Input, Bass, Mid, Treble or Output, **or are Fixed** (show the capture's setting, can't be turned, tooltip "Fixed at 6 in this capture"). A knob that is neither shows an amber "NOT SET" tag and can't be saved. A switch (bat toggle or push button) drives Level match or is Fixed (up/down, out/in). Knob scales: ticks, numbers 1–10, numbers 1–12, or none. Lights (pilot jewel or LED) light while the block is on or are always off.
- **The logo is always the Encore logo** (cream, white, gold or black; size can change).
- Faces are **composed to one cached image** (on save and when a show loads); Edit shows that image in the fixed amp box, with the driving controls and lit lights on top (GearView contract: same 600 × 430 box, so no layout moves). Nothing is drawn live on stage.
- Bodies: **Tall** and **Thin** combos, a **Head** (short box, deep framed panel, rubber feet), a **Grille head** (grille above a bottom panel) and **Top** (controls on the top surface, all-grille front), all in the same 600 × 430 box. Tolex includes tweed; grilles include perforated brass.
- Placement: 2 px grid, smart guides that line parts up with each other, equal-spacing snapping, and multi-select with Align / Space evenly / Same size.
- Five example amps on the board: **Encore Gold 30** (the Edit amp rebuilt), **JC-120** (a Jazz-Chorus-style combo), **Super Crush 100** (an Orange-style head: white framed panel, symbols instead of words, Fixed toggles, amber pilot light), **Blues Junior** (a tweed top-panel combo: chrome top panel, chickenhead knobs with 1–12 scales, FAT push button) and **5150 III 50W** (a three-channel grille head: perforated brass grille, gold bottom panel, oval badge, channel LEDs).
- **Scheduled (18 Nov):** build it after the other v3.2 steps (part B of `claude/PROMPT-V3.2-UI.md`). Engine work is only loading the preset's capture with the existing NAM loader; the rest is UI, assets and file format. New dependency: a WebP decoder (libwebp) or PNG conversion of the layers.
